# Learn From Session

1. Review the current conversation and supplied local evidence for the goal, outcome, failures, and corrections. Do not search private session stores.
2. Keep only reusable, actionable lessons. Exclude guesses, one-off accidents, secrets, and personal data. If none remain, stop without writing.
3. Propose exact text and a user-selected repository-local Markdown target. Distinguish a stated preference, evidenced project fact, operating rule, and recurring failure prevention; do not promote a guess into a rule.
4. Require explicit user approval of both text and target before writing. Preserve unrelated content. For a failure ledger, append rather than rewrite history.
5. Write only the approved change and verify it was saved. Do not claim durable learning until the write succeeds. Do not modify global memory or instructions automatically.

A useful lesson states the trigger, observed problem, preferred action, and a check that prevents recurrence. Report lesson, target, exact change, approval status, and save result. A proposal is not a completed update.
